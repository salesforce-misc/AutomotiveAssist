Source: "MFG User Journey (WIP)" spreadsheet — "Setup User Journey" tab (Rows 2–4) + "Commercial Excellence Transacti" tab (Row 2) + "AF" sheet from the Manufacturing & Rebate & PBB & Auto Data Shapes Quip doc. Contains 4 journeys (3 Setup + 1 Transaction) focused exclusively on the Sales Agreement feature within Manufacturing Cloud.
Authoring vs Runtime: Flows, journeys, and scenarios are authoring-layer constructs (human organization of test intent). Test cases and chains are runtime-layer (executor composition). This template populates the authoring layer only — runtime composition happens later via the pipeline.
SA Platform Limits (as of R264): Max 2,000 products per SA (UI Grid pagination blocks >2K; VOC 10K target blocked — P1 open). Max 72 schedules per SA (BT perm MAX_SALES_AGRMT_SCHEDULES_LMT; increasable to 120 max). Actuals Calculation is unsupported when SA Product Schedules >10K (DPE row-lock / OOM).

flow_name: Declares the business flow this journey belongs to. The import skill creates the flow and membership in one pass — equivalent to an in-lined /map-journeys. Journeys sharing the same flow_name are grouped into a single business_flow with flow_journeys edges.
prerequisite: Prose only. Structured journey-to-journey dependencies come from flow_name grouping + the /map-journeys skill post-import.
persona: Multi-persona OK at journey level (a journey CAN be executed by different personas). At scenario/ALT level, the rule is one persona per row.
data_shape_notes: References the AF sheet S/M/L volume data. Account distribution: 50% Non-Frequent (NF), 40% Normal, 10% Busy. These volumes determine which org tier is required for each scenario.

enabled → User manually specifies planned quantities
